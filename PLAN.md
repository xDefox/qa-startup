# webscope — план проекта

> Детерминированный движок веб-QA: находит проблемы на сайте, объясняет их языком
> владельца и отдаёт в машинно-читаемом виде, чтобы AI-агент мог их починить.

Статус: v0.3 (2026-10-22). Работает: CLI (scan/crawl/diff/history), MCP-сервер,
веб-интерфейс с историей и алертами, краулер с группировкой по шаблонам,
65 тестов, CI.

## 1. Продукт и покупатель

**Кто платит:** владелец сайта без технической команды — малый бизнес, услуги,
e-commerce, мастерские, студии. Не разработчик, не QA.

**Что он покупает:** «мой сайт в порядке / не в порядке и что мне делать» — без
терминов WCAG, без зелёных плашек «a11y: 74%».

**Почему это отличается от того, что уже есть:**

| | Lighthouse / PageSpeed | SignalCrawler и подобные | **webscope** |
|---|---|---|---|
| Кто пользователь | разработчик | QA/маркетолог | **владелец сайта** |
| Язык отчёта | технический | технический | **человеческий + что делать** |
| Оценка | метрики скорости | список правил | **балл 0–100 + план из 3 действий** |
| Регулярность | разовый прогон | разовый прогон | **еженедельно + диффы + алерты** |
| Цена | 0 | freemium/$$ | **дёшево, подписка за сайт** |

## 2. Проблема, которую решаем

У владельца сайта нет способа узнать, что сайт сломался, пока не пришли жалобы.
Инструменты есть, но они технические, разовые и не переводят «ошибка color-contrast»
в «половина ваших клиентов не читает текст на кнопке».

Мы даём **непрерывный контроль**: каждый прогон сравнивается с предыдущим, и
владелец получает «что сломалось с прошлого раза» — это и создаёт подписку.

## 3. Почему подписка, а не разовый скан

- Разовая проверка — товар: её заменяет бесплатный Lighthouse. Платить не будут.
- Регулярный мониторинг с диффами и алертами — услуга: за неё платят, потому что
  она ловит регрессии раньше, чем клиент.
- **Единица оплаты — сайт, не сканы и не места.** Агентство с 30 клиентскими
  сайтами платит за 30 сайтов; seat-based ценообразование в этом продукте убьёт продажи.
- **Churn — главный риск:** сайт починили → отписались. Лечится портфелем
  (агентство) и регулярной обязанностью (доступность/EAA требует перепроверки).

## 4. Центральная гипотеза: «общая структура сайтов»

Исходная идея автора: у всех сайтов одинаковые классы и атрибуты, поэтому можно
сделать универсальный набор проверок.

Уточнение после исследования рынка: **единица общности — не CSS-классы, а семантика
и роли**. Классы уникальны для каждого проекта (`.btn-primary` vs `.c-button`), а вот
`input`, `button`, `nav`, `form`, `label`, `alt`, `role`, `aria-*` стандартизированы
(HTML Living Standard + WAI-ARIA). На этом стоит `axe-core`.

Из этого следует **архетип-детектор**: по DOM/ARIA/meta определить стек и UI-кит
сайта и выбрать профильный набор проверок.

| Признак | Детектируется | Что меняем в проверках |
|---|---|---|
| `__NEXT_DATA__` / `data-reactroot` | React / Next.js | SPA-навигация, клиентские роуты, отсутствие SSR-контента |
| `Vue`, `data-v-*` | Vue | То же |
| `ng-version` | Angular | То же |
| `wp-content` | WordPress | Темы/плагины: полный путь к шаблону, доступность тем |
| `Shopify.theme`, `cdn.shopify` | Shopify | Проверка чек-аута, `Shopify.pay`, политики возврата |
| классы `ant-*` | Ant Design | Компонентные a11y-паттерны |
| классы `Mui*` | MUI | То же |
| `btn btn-`, `col-` | Bootstrap | Сетка: переполнение на 320px |
| utility-классы (`flex`, `px-`, `text-`) | Tailwind | Утилитарный CSS: текст-контраст по вычисленным стилям |

Архетип — **внутренний механизм выбора проверок**, а не маркетинговая фишка.

## 5. Архитектура

```
                    ┌───────────────────────────────┐
  CLI (scan/crawl)  │                               │
  MCP (stdio)       │   webscope.core               │
  CI (exit code)    │   ┌───────────────────────┐   │
  Веб (FastAPI)     │   │ crawler: robots,     │   │
                    │   │ sitemap, templates   │   │
                    │   │ scanner: playwright  │   │
                    │   │ ├ archetype detector │   │
                    │   │ └ checks/*           │   │
                    │   │   ├ a11y (axe-core)   │   │
                    │   │   ├ content           │   │
                    │   │   ├ forms             │   │
                    │   │   ├ links             │   │
                    │   │   ├ console/network   │   │
                    │   │   └ viewport/targets │   │
                    │   ├ scoring: 0–100 +     │   │
                    │   │ human wording        │   │
                    │   ├ history: snapshot,   │   │
                    │   │ diff, trend          │   │
                    │   └ report: text | plain |  │   │
                    │           json | html |   │   │
                    │           sarif | fix     │   │
                    └─────────────┬─────────────┘   │
                                  │                  │
                    ┌─────────────┴─────────────┐    │
                    │   webscope.webapp         │    │
                    │   scheduler → monitor →   │    │
                    │   SQLite (sites, runs,    │    │
                    │   findings) → diffs →     │    │
                    │   alerts (email, Telegram)│    │
                    └───────────────────────────┘    │
```

Принципы слоёв:

- `checks/*` — чистые функции `(page, ctx) -> list[Finding]`. Не знают про отчёт и MCP.
- `scanner.py` — оркестрация: браузер, архетип, контекст, evidence-сбор.
- `crawler.py` — обход сайта; `history.py` — снимки/диффы; `scoring.py` — балл и язык.
- `models.py` — схема данных, версионируется (semver на формат JSON).

## 6. Схема данных

```jsonc
{
  "schema_version": "1.0",
  "url": "https://example.com",
  "final_url": "https://example.com/",
  "title": "Example",
  "archetype": {"framework": "next", "cms": null, "ui_kit": "tailwind"},
  "duration_ms": 3120,
  "pages_scanned": 1,
  "findings": [
    {
      "rule": "content/image-alt",
      "severity": "serious",          // critical | serious | moderate | minor
      "title": "Изображение без alt",
      "message": "У <img> нет атрибута alt",
      "url": "https://example.com/",
      "selector": "main > div:nth-child(2) > img",
      "snippet": "<img src=\"/logo.png\">",
      "help_url": "https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html",
      "source": "webscope.content",
      "details": {"evidence": "002_content_image_alt.png"}
    }
  ],
  "summary": {"critical": 0, "serious": 1, "moderate": 4, "minor": 2, "total": 7}
}
```

Совместимость: `schema_version` — semver. Поля только добавляем, не удаляем.

## 7. Набор проверок

| Check | Что ловит | Severity |
|---|---|---|
| `a11y` | axe-core, теги wcag2a/2aa, wcag21a/21aa, wcag22aa, best-practice | по impact |
| `content` | `lang`, `charset`, `title`, description, viewport, h1, порядок заголовков, `img` без alt, `iframe` без title, пустые ссылки/кнопки, дубли id | serious → minor |
| `forms` | input без label, label только через placeholder, input без `name`, email без `autocomplete`, submit без доступного имени | serious → minor |
| `links` | `href="#"`, `target=_blank` без `rel=noopener`, битые внутренние ссылки, mixed content | serious → minor |
| `console` | ошибки/варнинги в консоли, uncaught exceptions, упавшие запросы (4xx/5xx) | serious → moderate |
| `viewport` | горизонтальный overflow на 320px и 768px, элементы вне вьюпорта, target size < 24×24 (WCAG 2.2, 2.5.8) | serious → minor |

## 8. MCP-инструменты

```
scan_page(url, checks?, timeout_ms?) -> ScanResult(JSON)
list_findings(url, min_severity?)    -> краткий список
get_fix_prompt(url, rules?)          -> готовый промпт для coding-агента
```

`get_fix_prompt` — ключевая фишка для аудитории разработчиков: он собирает из
находок **задачу для агента** (что сломано, селектор, HTML, критерий WCAG, критерий
приёмки). Агент применяет правку и перезапускает `scan_page` — цикл замыкается.

## 9. Дорожная карта

### Milestone 0 — ядро ✅
CLI, 6 проверок, архетип-детектор, evidence, тесты, CI.

### Milestone 1 — MCP ✅
Сервер `stdio`, 3 тула, smoke-тест. Осталось проверить вручную цикл «агент починил».

### Milestone 2 — краулер ✅
robots.txt, sitemap.xml (+ sitemap index), обход по ссылкам, группировка по шаблонам

### Milestone 3 — история и диффы ✅ (локально)
Снимки в JSON, диффы (новые/исправленные/изменённые), тренд по прогону, `--history-dir`.

### Milestone 4 — массовый продукт: MVP ✅ (веб-интерфейс) / ⏳ (оплата)
1. **Веб-интерфейс**: ✅ вставил URL → отчёт, без регистрации, отчёт на языке владельца.
2. **Планировщик**: ✅ еженедельный/ежедневный прогон по расписанию сайта.
3. **История и диффы в базе**: ✅ SQLite (сайты, прогоны, находки, диффы).
4. **Алерты**: ✅ email (SMTP) и Telegram, когда набор находок изменился.
5. **Биллинг**: ⏳ Stripe, подписка per-site — только после первых платящих клиентов.
6. ⏳ Аккаунты и оплата без карты для первого скана (сейчас без регистрации).

### Milestone 5 — проверка спроса (идёт параллельно, дешевле кода)
- Лендинг: «Проверьте сайт бесплатно» → собираем заявки. Веб-интерфейс уже
  работает как этот лендинг — осталось повесить домен и форму заявки.
- 10–15 разговоров с владельцами сайтов и агентствами: как проверяете сейчас,
  сколько платите за аудит, что было бы «достаточно хорошо».
- 3–5 платящих пилота (ручной мониторинг нашим движком) — проверяем, что отчёт
  действительно приводит к действию.

## 10. Метрики

**North star:** доля отчётов, после которых владелец реально что-то исправил
(через дифф: появился прогон «исправлено N проблем»).

- Time-to-first-report < 60 секунд.
- Доля отчётов, где владелец дочитал до конца (в веб-версии — скролл).
- FP-rate < 10% (доля находок, отклонённых как ложные).
- Retention: повторные сканы (weekly+) > 40%.
- Стабильность оценки: повторный прогон даёт тот же балл.

## 11. Риски

| Риск | Митигация |
|---|---|
| False positives | evidence-first: подтверждение в браузере, скриншот, сниппет; наша проверка вместо дубля axe |
| Галлюцинации LLM | LLM не создаёт находки; всё детерминировано и версионируется |
| Churn (починили → отписались) | портфель агентств, регулярная обязанность (доступность), weekly-алерты как привычка |
| Отчёт без actionability | `plain`-формат: «почему это важно» + «что делать» + топ-3 задачи |
| SSRF / безопасность | Только `http/https`; блок localhost, link-local, private IP (DNS-resolve + проверка редиректов); таймауты; лимит страниц |
| Юридика и robots | Уважаем `robots.txt` по умолчанию; не обещаем «compliant за 48 часов» (FTC оштрафовал overlay-вендоров за такие формулировки) |
| Стоимость хостинга | Один браузер на прогон, кэш контекста, ограничение страниц и времени |
| Шум от «мелочей» | Отдельная секция «мелочи», в топ-3 действий они не попадают |

## 12. Конкурентное позиционирование

| | Lighthouse | SignalCrawler / GoQA / TestOptim | Метрика/скан-сервисы | **webscope** |
|---|---|---|---|---|
| Тип | бесплатный инструмент | SaaS-платформы | разовые отчёты | **подписка + OSS-ядро** |
| Язык | технический | технический | смешанный | **человеческий** |
| Регулярность | разово | по запросу | разово | **еженедельно + диффы** |
| Цена | 0 | $$ | $ | **$ (дёшево, per-site)** |
| Канал | поиск | SEO/продажи | SEO | **SEO + партнёрки (Shopify/Tilda) + OSS** |

Мы не конкурируем с ними в «отчётах» — мы даём **непрерывность** и **язык владельца**.

## 13. Открытые вопросы (проверить на пользователях)

1. Сколько платят за разовый аудит сейчас и за что: за страницу, за сайт, за час?
2. Что важнее: список проблем или «сайт сломался вот здесь» (алерт)?
3. Кто платит: владелец сам или агентство за клиента?
4. Нужна ли авторизация для приватных стендов и как хранить секреты.
5. Какие каналы: SEO по запросу «проверка сайта», партнёрки CMS, агентства?
6. Нужен ли домен под вертикаль (e-commerce, услуги, медицина) для профильных чек-листов.
