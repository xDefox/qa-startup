# webscope

Детерминированный движок веб-QA: обходит сайт, подтверждает каждую находку в
реальном браузере и отдаёт результат в машинно-читаемом виде — в том числе как готовое
ТЗ для AI-кодинг-агента.

```
webscope scan https://example.com --format json
webscope crawl https://example.com --history-dir .webscope
webscope scan https://example.com --fix-prompt > fix.md
claude mcp add webscope -- webscope mcp
```

## Идея

У всех сайтов общая структура: формы, кнопки, ссылки, заголовки, изображения — это
одни и те же семантические конструкции (`input`, `button`, `label`, `alt`, ARIA-роли).
На этом держится возможность написать универсальный набор проверок, который работает
на любом сайте без настройки.

Принцип работы: **код измеряет, браузер подтверждает, AI объясняет**.
LLM никогда не создаёт находки — он только объясняет уже подтверждённые.

Полный план проекта — в [PLAN.md](PLAN.md).

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
playwright install chromium   # либо используется системный Chromium
```

## Использование

### CLI

```bash
# текстовый отчёт
webscope scan https://example.com

# JSON для пайплайна
webscope scan https://example.com --format json --out report.json

# SARIF для GitHub Code Scanning
webscope scan https://example.com --format sarif --out results.sarif

# ТЗ для coding-агента
webscope scan https://example.com --fix-prompt

# только часть проверок, со скриншотами находок
webscope scan https://example.com --checks a11y,forms --evidence-dir evidence/

# CI: код возврата 1, если есть находки от serious и выше
webscope scan https://example.com --fail-on serious
```

### Обход сайта, история и сравнение

```bash
# обойти сайт и проверить по одной странице каждого шаблона (/catalog/1 и /catalog/2 — один шаблон)
webscope crawl https://example.com --max-pages 30 --depth 2

# тот же обход, но с сохранением снимка и сравнением с прошлым прогоном
webscope crawl https://example.com --history-dir .webscope

# отчёт для владельца сайта: без терминов, с оценкой и планом из 3 действий
webscope crawl https://example.com --format plain

# сравнить два снимка вручную
webscope diff .webscope/old.json .webscope/new.json

# динамика по прогону: оценка и количество проблем по дням
webscope history https://example.com --dir .webscope
```

История хранится рядом: `.webscope/<домен>/<метка>.json` + `latest.json`.
Формат снимка — тот же JSON, что у `scan --format json`, поэтому его можно
скармлить в свой пайплайн.

### Форматы отчётов

| Формат | Для чего |
|---|---|
| `text` | Технический отчёт для разработчика |
| `plain` | Отчёт для владельца сайта: оценка 0–100, «почему это важно», «что делать» |
| `json` | Для пайплайнов и агентов |
| `html` | Отчёт для отправки клиенту или вложения в письмо |
| `sarif` | GitHub Code Scanning |
| `junit` | JUnit XML для CI |

### MCP

```bash
webscope mcp
```

Инструменты:

| Инструмент | Назначение |
|---|---|
| `scan_page(url, checks, timeout_ms)` | Полный скан, результат в JSON |
| `list_findings(url, min_severity)` | Краткий список находок |
| `get_fix_prompt(url, rules)` | Готовое ТЗ для исправления находок |

Цикл работы агента: `scan_page` → `get_fix_prompt` → правка кода → `scan_page` повторно.

### Веб-интерфейс

Для владельца сайта: вставил адрес — получил отчёт с оценкой и планом действий.

```bash
pip install -e ".[web]"
WEBSCOPE_AUTH_PASSWORD='сложный-пароль' webscope serve --db webscope.db --port 8000
```

Без `WEBSCOPE_AUTH_PASSWORD` кабинет работает в демо-режиме и доступен всем,
кто дотянется до порта: `webscope serve` печатает об этом предупреждение.
Логин по умолчанию — `admin` (`WEBSCOPE_AUTH_USER`), сессия — подписанная
HttpOnly-cookie, пароль в ней не хранится.

Что внутри:

- проверка стартует сразу, отчёт открывается сам — пока идёт проверка, страница
  показывает спиннер «Идёт проверка» (без перезагрузки, через `fetch`);
- можно загрузить локальную сборку (папку с `index.html`) — проверка бегает
  по файлам, которые раздаёт само приложение;
- отчёт на человеческом языке: оценка 0–100, «почему это важно», «что делать»;
- история проверок: прошлый балл показывается «заклеенным» рядом с текущим,
  таблица находок с источником и ссылкой на документацию правила;
- **«Сохранить отчёт»** — отдельная карточка в конце страницы отчёта, чтобы
  не спорить с главным действием «Проверить ещё раз»: HTML (прочитать
  в браузере), JSON (интеграции), TXT (терминал или письмо), JUnit XML
  (CI: Jenkins, GitLab, pytest) и SARIF (GitHub Code Scanning). Файл приходит
  вложением с именем вида `webscope-example.com-2026-10-30.json`;
- **кабинет управления** (`/sites/{id}/settings`): email/Telegram для отчётов,
  расписание, удаление сайта с историей;
- автоматические проверки по расписанию (день / неделя / месяц);
- алерты о том, что сломалось с прошлого раза: новые проблемы и старые, ставшие
  серьёзнее — на email (`SMTP_*`) и в Telegram (`TELEGRAM_BOT_TOKEN`).

API (JSON) для интеграций: `/api/sites`, `/api/sites/{id}`, `/api/sites/{id}/runs`,
`/api/sites/{id}/report.{html,json,txt,xml,sarif}` (`?download=1` — отдать файлом
с `Content-Disposition: attachment`), `POST /api/sites/{id}/scan`.

## Проверки

| Check | Что ловит |
|---|---|
| `a11y` | axe-core: WCAG 2.0/2.1/2.2 A/AA, best-practice |
| `content` | `lang`, `title`, description, viewport, og-теги соцкарточки, заголовки, `alt`, `iframe`, пустые ссылки/кнопки, дубли `id` |
| `forms` | подписи полей, `name`, `autocomplete`, доступные имена кнопок |
| `links` | `href="#"`, `target=_blank` без `noopener`, mixed content, битые внутренние ссылки |
| `console` | ошибки и предупреждения консоли, упавшие запросы |
| `viewport` | горизонтальный overflow на 320/768px, размер целей касания < 24×24 |
| `site` (обход) | одинаковые `title`/`description` у страниц одного шаблона |

`site`-проверки считаются по всему обходу (`crawl`), а не по одной странице:
группировка краулера по шаблонам превращает «300 URL» в «8 шаблонов» и ловит
дубли, которые на отдельной странице не видны.

Доступное имя ссылки и кнопки считается по спеке accname: `aria-labelledby` →
`aria-label` → нативное имя → содержимое (текст потомков, `alt` у картинок,
`<title>` у svg) → `title`. Скрытое (`aria-hidden`, `display:none`) в имя не
идёт. Находки, совпадающие с axe-правилом, схлопываются в одну — по элементу,
а для проверок уровня документа (`lang`, `title`, `h1`) — по URL страницы.

## Когда страница не открывается

Вместо общей фразы «сайт недоступен» движок называет причину — её видно
в CLI, в веб-отчёте и в алерте по расписанию:

| Ситуация | Что увидите |
|---|---|
| Опечатка в домене / запись ещё не создана | `домен не найден` |
| Сайт не поддерживает HTTPS | `сломан HTTPS-сертификат` |
| Сервер перегружен или молчит | `не загрузилась за N с` |
| Страница удалена / требует доступ / ошибка сервера | `HTTP 404` / `403` / `500` с пояснением |

## Безопасность

Веб-кабинет содержит адреса сайтов, расписание и адреса алертов, поэтому:

- **Вход включается паролем**: `WEBSCOPE_AUTH_PASSWORD` (+ `WEBSCOPE_AUTH_USER`,
  по умолчанию `admin`). Пока пароль не задан, кабинет открыт (демо-режим),
  и `webscope serve` предупреждает об этом. Сессия — HttpOnly/SameSite-cookie
  с HMAC-токеном; пароль в cookie не попадает, смена пароля разлогинивает всех.
- **Пароли к защищённым сайтам шифруются** (`WEBSCOPE_AUTH_KEY`, Fernet):
  в базе лежит `fernet:…`, наружу отдаётся только флаг «вход настроен».
  Без ключа пароли, как и раньше, хранятся открытым текстом — `webscope serve`
  предупреждает об этом.
- **CSRF**: POST с чужим `Origin`/`Referer` отклоняется (403).
- **Лимиты запуска**: `WEBSCOPE_RATE_LIMIT` (запусков с адреса за окно,
  по умолчанию 20), `WEBSCOPE_RATE_WINDOW` (окно, секунды, по умолчанию 60) и
  `WEBSCOPE_MAX_CONCURRENT_SCANS` (параллельных прогонов, по умолчанию 2).
  Счётчик в памяти процесса — для нескольких воркеров нужен общий (Redis).
- **Загрузка локальной сборки**: путь проверяется по `resolve()`, абсолютные пути
  и выход за каталог задания отклоняются; лимиты — 300 файлов, 10 МБ на файл,
  50 МБ на загрузку; хранятся последние 50 загрузок.
- **Песочница `/__local/`**: загруженный HTML отдаётся с `Content-Security-Policy:
  sandbox`, поэтому его скрипты не видят cookie и `/api` приложения.
- **Документация API** (`/docs`, `/redoc`) выключена; `/openapi.json` доступен
  только после входа.

Движок:

- Только `http/https`, без credentials в URL.
- **SSRF-защита на каждом запросе**, а не только на стартовом адресе: браузер
  (`context.route`) и HTTP-клиенты (`netguard.GuardedTransport`) не пускают
  приватные, loopback и link-local адреса — в том числе после редиректа.
  Обход — `--allow-private` / `WEBSCOPE_ALLOW_PRIVATE=1` и только для своих стендов.
  Исключение — файлы, залитые через веб-интерфейс: их сканирует само приложение
  по своему `/__local/`, чужие loopback-адреса остаются закрыты.
- Проверка ссылок идёт с проверкой TLS-сертификата (`verify=True`);
  отдельно различаются «ссылка битая» (`links/unreachable`) и «не дождались
  ответа за 8 с» (`links/timeout`, в балл не идёт).
- У прогона есть бюджет времени — `WEBSCOPE_SCAN_TIMEOUT` (по умолчанию 600 с):
  проверка не может висеть часами на медленном сайте. Не успели — в отчёт
  уходит диагностика `scan/timeout` с числом проверенных шаблонов.
- SARIF несёт `partialFingerprints`: GitHub Code Scanning склеивает находки
  между прогонами, а не создаёт новый алерт на каждую проверку.
- Диффы устойчивы к смене разметки: находки сопоставляются по нормализованному
  фрагменту элемента, а не по сгенерированным `id`, которые меняются между рендерами.
- Скриншоты и разметка попадают в локальный каталог `--evidence-dir`.
- Сканирование чужих сайтов — только те, на которые у вас есть право проверять;
  по умолчанию уважается `robots.txt` — и в обходе (`crawl`), и в одиночном
  `scan` (обход — `--ignore-robots`, только для своих стендов). 403 на
  `robots.txt` означает «обход запрещён», 401 — «представьтесь»: закрытый
  стенд не превращается в пустой сайт.
