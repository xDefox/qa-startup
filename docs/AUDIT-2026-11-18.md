## 1. КРИТИЧНО (P0) — исправить перед любым релизом

### P0-1. Регрессия в `src/webscope/scanner.py` (незакоммиченные изменения)

`git diff` показывает 7 вставок / 1 удаление в `_scan_page`:

- Удалена строка `page.evaluate(JS_UTILS)  # bypasses CSP` — она заменена на **дубликат** проверки `page.url.startswith("chrome-error://")` (та же проверка стоит сразу выше).
- `JS_UTILS` импортируется (`from .checks.js import JS_UTILS`), но больше не используется — `ruff` фиксирует `F401 unused import`.
- Сообщение об ошибке `HTTP 401 — ...` жёстко закодировано для любой ошибки браузера (DNS, таймаут, TLS) — вводит в заблуждение.

**Последствия:** утилиты JS не инъектируются в страницу при сканировании — проверки, зависящие от `JS_UTILS` (DOM-helpers, доступные имена, hit-test и т.п.), могут молча ломаться или возвращать неверные результаты. Дублирование проверки не несёт пользы, ложная метка «401» портит диагностику.

**Файл:** `src/webscope/scanner.py` (строки ~614-630, не закоммичено)  
**Действие:** восстановить `page.evaluate(JS_UTILS)`, убрать дубликат, сделать диагностику `chrome-error://` точной (`diagnose_navigation_error`).

### P0-3. Docker-образы не воспроизводимы / не соберутся

- `Dockerfile` stage builder использует **poetry** (`pip install poetry`, `poetry install --only=main`) и копирует `poetry.lock*` — но в репозитории **нет `poetry.lock`** (`git ls-files` подтверждает). `pyproject.toml` при этом использует бэкенд `setuptools`, а не `poetry` — инструменты не согласованы.
- `Dockerfile` на базе `python:3.12-slim`, но `pyproject.toml` требует `requires-python = ">=3.13"` — образ не соберётся/не пройдёт проверку зависимостей.
